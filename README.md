# 电商销售数据分析：GMV 下滑归因

以完成订单 GMV 为北极星指标，用「量 × 率 × 价」三因子拆解定位 GMV 下滑的主因，流程覆盖数据质量检查、MySQL 入库、SQL 月度指标计算与趋势可视化。

**数据范围**：2025-06 ~ 2026-05，共 5000 条订单记录
**数据来源**：[Heywhale 电商销售数据分析](https://www.heywhale.com/mw/project/6ab783ce6493bced74f5bdd4/dataset)

## 二、指标体系

**北极星指标：完成订单GMV**

> 口径：统计订单日期 2025-06 ~ 2026-05 的订单金额，业务状态为「已完成」（排除待发货、已取消、退款中），按订单ID去重，单位：元

**驱动指标**

| 指标      | 口径                              | 单位  |
|:------- |:------------------------------- |:--- |
| 总下单量    | 四种状态（已完成、待发货、已取消、退款中）订单，按订单ID去重 | 单   |
| 商品交易成功率 | 完成订单数 / 总下单量                    | %   |
| 客单价     | 完成GMV / 完成订单数                   | 元   |

**护栏指标**

| 指标      | 口径                     | 单位  |
|:------- |:---------------------- |:--- |
| 完成订单促销率 | 是否促销为 1 的完成订单数 / 完成订单数 | %   |

**恒等式**（12 个月逐月验证均成立）：

```
完成订单GMV = (总下单量 × 商品交易成功率) × 客单价
```

## 三、数据质量检查

`py/data.py` 以断言方式对全量数据做校验，全部通过：

- **字段完整性**：12 列齐全（订单ID、用户ID、订单日期、商品分类、商品名称、购买数量、单价、订单金额、支付方式、用户所在地区、是否促销、订单状态）
- **主键唯一**：订单ID 无重复，主键假设成立

- **日期范围**：全部落在 2025-06-01 ~ 2026-05-31，无越界记录
- **字段间逻辑**：订单ID 内嵌日期与订单日期 100% 一致；`是否促销` 与实付金额自洽（促销单均有折扣，非促销单均为全价）

## 六、技术点

- **口径先行**：先定义北极星指标与各驱动指标的业务口径（状态过滤 + 主键去重），再取数，避免口径漂移
- **三因子对数分解归因**：`GMV = 总下单量 × 商品交易成功率 × 客单价`，对各因子取对数做连乘分解，因子对数变化率占 GMV 对数变化率的比重即贡献占比（合计 100%），据此定位主因
- **SQL**：CTE 分层（`base_order` → `distinct_order` → `monthly`）、`CASE WHEN` 条件聚合、`NULLIF` 防止除零
